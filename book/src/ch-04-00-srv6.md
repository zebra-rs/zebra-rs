# SRv6

## Cisco IOS-XR uSID Convention

The Cisco IOS-XR uSID convention partitions the 16-bit micro-SID space into
the following ranges:

| Range | Cisco Term | Purpose | Format |
|---|---|---|---|
| `0x0000 – 0xDFFF` | GIB | Global node IDs (uN) | high nibble 0-D |
| `0xE000 – 0xE063` | LIB (default) | IGP-dynamic local SIDs (uA) | high nibble E |
| `0xE064 – 0xFEFF` | ELIB | Operator-pinned static SIDs (uDT6 etc.) | high nibble E or F |
| `0xFF00 – 0xFFEF` | W-LIB | Wide-format local SIDs | high nibble F |
| `0xFFF0 – 0xFFF7` | EW-LIB | Explicit W-LIB | high nibble F |

## `show segment-routing srv6 sid`

The SRv6 SIDs the daemon has allocated from its locators, one per line:

- **`Behavior`:** `End`, `End.X`, `uN`, `uA`, `End.DT46`, `End.DT2U`, and
  so on. `uA(LIB)` is a uA SID's twin in the local ID block, the
  `block:function` form a NEXT-C-SID packet carries after the uN shift.
- **`Context`:** an End.X or uA SID's outgoing interface, or `-`.
- **`Protocol`:** the protocol that owns the SID, such as `isis`, `ospfv3`
  or `bgp`.
- **`Locator`** the SID was carved from.
- **`AllocationType`:** `dynamic`.

A SID under egress protection that is redirecting traffic shows the
redirect on the line below it:
`-> egress-protection redirect: H.Encaps to <Mirror SID>`.

```
r1> show segment-routing srv6 sid
 SID                 Behavior   Context              Protocol          Locator   AllocationType
 -----------------------------  -------------------  ----------------  --------  ----------------
 fcbb:bbbb:1::       uN         -                    ospfv3            LOC1      dynamic
 fcbb:bbbb:1:e000::  uA         Interface 'r1-r2'    ospfv3            LOC1      dynamic
 fcbb:bbbb:1:e001::  uA         Interface 'r1-r3'    ospfv3            LOC1      dynamic
 fcbb:bbbb:e000::    uA(LIB)    Interface 'r1-r2'    ospfv3            LOC1      dynamic
 fcbb:bbbb:e001::    uA(LIB)    Interface 'r1-r3'    ospfv3            LOC1      dynamic
```

This is r1 from the four-router network of the
[OSPFv3 show page](ch-15-18-ospfv3-show.md), with uSID locator
`fcbb:bbbb:1::/48` for OSPFv3: a uN SID, and a uA SID and its LIB twin
for each adjacency.

JSON: `{ "entries": [ { "sid", "behavior", "context", "owner",
"locator", "allocation_type", "redirected_to" } ] }`, where
`redirected_to` appears only while a redirect is in place.
